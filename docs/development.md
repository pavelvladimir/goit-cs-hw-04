# Розробка й тести

Використовую Python 3.14 та uv. Залежності для розробки зафіксовані в `uv.lock`:

```bash
make init
make check
```

`make check` запускає Ruff, перевірку Markdown, strict mypy та pytest з покриттям
рядків і гілок. Мінімальний поріг — 90%. Дані покриття збираються також із дочірніх
процесів; звіти зберігаються в `htmlcov/index.html` і `coverage.xml`.

## Окремі команди

- `make demo` — запуск на прикладах із `data/`.
- `make test` або `make coverage` — тести без решти перевірок.
- `make lint`, `make typecheck`, `make format` — стиль, типи й форматування.
- `make benchmark` — порівняння швидкості.
- `make check-rocky` — перевірка в Docker на Rocky Linux.

Повний список показує `make`. У `.vscode/` є налаштування інтерпретатора,
тестів і форматування. Кеш uv зберігається в `.uv-cache/`.

## Що перевіряють тести

Перевіряю однаковий результат усіх трьох способів пошуку, Unicode, межі блоків,
порожні дані, повтори, відсутні файли та помилки доступу. Блоковий пошук додатково
порівнюється з простим пошуком у цілому рядку на даних із фіксованим random seed.

Потоки й процеси в тестах справжні: перевіряється одночасна робота та розподіл файлів
між PID. Окремі тести відтворюють обрив Queue, гонку під час завершення, timeout
і невдалий запуск процесу. Є також перевірки CLI та benchmark.

Менеджеру черги потрібні локальні Unix sockets, тому надто обмежений sandbox може
завадити запуску. Зовнішня мережа для тестів не потрібна.

## Результати

Повний прогін від 22.10.2026, CPython 3.14.6:

| Середовище | Тести | Покриття рядків і гілок |
| --- | --- | --- |
| macOS ARM64 | 91 пройдено | 100% |
| Rocky Linux 10.2 ARM64 у Docker Desktop | 91 пройдено, без пропусків | 100% |

Ruff, Markdown і mypy також пройшли. Приклади повернули однакові словники.
Локальні журнали — `artifacts/check.log` і `artifacts/check-rocky.log`.

Windows, Linux x86_64 і нативний Rocky/RHEL із SELinux не перевірялися.
Докладніше про контейнер — у [нотатках про Rocky Linux](rocky-linux.md).
