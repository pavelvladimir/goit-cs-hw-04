# Як працює пошук

Спільну логіку виніс у `search_common.py`, щоб потоки й процеси відрізнялися
способом виконання, а не самим пошуком.

## Читання файлів

Файл читається блоками по 65 536 символів, без завантаження всього тексту в пам'ять.
Між блоками зберігається хвіст завдовжки `довжина найдовшого слова − 1`
після перетворення регістру, щоб не загубити збіг на межі. Для пошуку без регістру використовую
`casefold()` — він працює і з Unicode, наприклад `Straße` та `STRASSE`.

Шлях додається до результату тільки після успішного читання всього файлу.
Якщо наприкінці трапляться пошкоджені UTF-8 байти, файл не потрапить до результату,
навіть якщо слово вже знайшлося. Помилки доступу та декодування збираються окремо;
каталоги, FIFO й пристрої не передаються на читання.

## Потоки й процеси

Файли розподіляються по черзі: перший — першому виконавцю, другий — другому тощо.
Виконавців не більше, ніж файлів. Розміри файлів при розподілі не враховуються,
тому однакова кількість файлів не завжди означає однакове навантаження.

Кожен потік формує свій результат. `Lock` захищає лише додавання готового результату
до спільного списку, а не читання чи пошук. Після `join()` результати об'єднуються.

Процеси запускаються через `spawn` і передають результати через `Manager().Queue()`.
Менеджер тут потрібен через конкретний випадок: падіння виконавця посеред передавання
великого повідомлення могло залишити звичайну `Queue` у блокувальному читанні.
Окремий процес менеджера усуває це зависання, але додає накладні витрати.

Для процесів є `--timeout`, за замовчуванням 60 секунд. При збої незавершені процеси
зупиняються, а їхні ресурси звільняються. Після завершення всіх виконавців черга
перевіряється ще раз, щоб не пропустити останнє повідомлення.

## Використання з Python

`search_threaded(files, keywords, workers=4)` і
`search_multiprocess(files, keywords, workers=4)` повертають `dict[str, list[str]]`.
Для отримання помилок можна передати список через `errors=`, інакше вони йдуть у logging.
Виклик процесної версії має бути всередині `if __name__ == "__main__":`.

CLI повертає `0` при успіху, `1` при помилках обробки, `2` для неправильних аргументів
і `130` при Ctrl+C. Повідомлення про помилки йдуть у stderr.

## Обмеження

- Пошук буквальний: без регулярних виразів і перевірки меж слова.
- Unicode NFC/NFD не нормалізується; CRLF та LF залишаються різними послідовностями.
- Різні шляхи чи посилання на той самий файл вважаються окремими входами.
- Файли не блокуються від змін під час читання.
- Timeout стосується лише процесів і не є жорсткою гарантією часу завершення:
  запуск та прибирання можуть затриматися. Для потоків примусового timeout немає.
